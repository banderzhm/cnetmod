# HTTP/3 生命周期、回收与恢复回归

本轮以 `11e4930f` 的职责拆分和 `1caf610a` 的不可变响应头缓存为基础，
仅在 `fix/http3-arena-performance` 提交。生产代码由 GPT-6.1-sol 子代理实现，
主代理审核取消、内联恢复、流控和回收路径，并协调两平台串行验证。

## 修复边界

- QUIC 流状态：校验 RESET 方向、额度和 final size；FIN 不得缩小已接收偏移；
  单向流不存在的方向初始化为关闭。取消接收后仍保留最终大小核算，丢弃字节只归还一次。
- 流生命周期：RESET-first 流也有会话清理责任方；真正退休后才归还 MAX_STREAMS。
  按真实退休数批量更新，饱和于协议上限，避免逐请求控制帧及高 ID 提前归还低 ID 的额度。
- 取消与协程：读就绪对象在内联恢复期间持有所有权；不跨异步锁保存容器迭代器；
  QPACK 取消通过所属事件循环派发并等待回调退出。流式业务处理器和接收协程各用独立令牌，
  业务提前返回、错误和外部取消均先停止接收，再汇合释放。
- HTTP/3 内存：请求体有可配置上限；控制流增量消费前缀；未完成控制帧及 QPACK 插入缓存有界；
  QPACK 等待者在连接退出前唤醒；关键单向流关闭发送正确的应用错误码。
- 发送及关闭：优先级元数据在流退休时删除，重传帧保存必要优先级；关闭时统一清空发送队列、
  恢复记录和流状态，失败写请求，取消接收并等待已有写协程。写完成通知在释放接收锁后派发。
- 0-RTT：早期数据进入丢包恢复；Retry 保持包号单调，只重新提交未确认数据；
  取得 1-RTT 密钥后不再发送 0-RTT；拒绝早期数据时清除恢复别名并交给 HTTP 安全回退。
  包预算、拥塞窗口及加密失败路径均保留未提交帧。

普通响应保留不可变头部、共享响应体及单次写入路径。取消适配器只用于需要并发取消的
流式分支；流控回收增加两个计数器，不增加逐请求分配。

代码提交：`e1c6da60903444f5a1734ea00636e855e5b446b8`。

Windows 原生 curl 不支持 HTTP/3，未安装原生 nghttp3 client/server，因此三项明确跳过，
不能计为通过；对应的 curl、nghttp3 双向验证均在 Linux 实际通过。
Windows 循环内存呈波动，不能称为平线或证明无限期零增长；长连接固定采样与 30 轮结果
只覆盖本次测试窗口。Linux 同样不把有限窗口稳定扩展为无限时长保证。

新增 MAX_STREAMS 用例对旧二进制实际失败：初始额度 100，仅退休最高 ID 流便升到 200；
最终二进制为 100 → 100，其余流回收后才到 200。见 `linux/stream-credit-before-fix.log`
和 `linux/ctest.log`。0-RTT 故障代理在最终测试中实际延迟 Retry 20 次、观察 Retry 前
早期数据 10 次、丢弃 Retry 后早期数据 2 次，Initial 包号倒退为 0。
早期代理曾仅按 UDP 源地址聚合包号而报告一次倒退；该失败原样保存在
`linux/proxy-before-cid-fix.log`。代理现按客户端 CID 区分连接并保留严格断言及事件字段；
旧日志缺连接身份，不能事后证明那次报告的具体原因。

## 证据说明

`linux/`、`windows/` 保存最终构建、CTest、跨实现互操作和持续内存回归证据；
`reproduce/` 保存本机串行测试脚本，路径需按复现环境调整。
内存测试在同一服务进程上先运行一个连接 10,000 次流操作，再运行 30 轮生命周期场景，
每轮检查仅剩探测连接。前 5 轮作为内存统计预热，原始样本全部保留。
功能通过与内存趋势分别报告；活动连接归零不等于内存绝对不增长。

官方性能复测固定 HttpArena `8977be2721a5aba7b320345cddfcd6f6b654e698`，
同一台机器、64 连接、64 流、64 客户端线程、每轮 5 秒、3 轮、轮间冷却 2 秒。
使用官方最佳有效 `2xx / elapsed`，不使用 h2load headline 替代。
三个框架的 baseline-h3 和 static-h3 逐项串行运行，计时期间没有构建或其他测试。

## 同条件性能对照

首轮 host 网络测量时，Windows 进程占用 8082，使两个对照框架的附带 TCP 入口启动失败。
`official-host-port-conflict/` 原样保留该轮日志及 cnetmod 结果，不用于排名。
随后三方全部重测：同一个 Docker `--network none` 容器仅保持网络命名空间，所有服务
及原生 h2load 在其中共用 loopback。没有 Docker bridge/NAT；对照镜像、配置、8443 端口、
官方负载参数和 CPU 策略未改。具体命令及仅改变网络归属的补丁见
`official-isolated/records/network-isolation.patch` 和复现脚本。
这组数值只进行组内比较，不与 host 网络或历史结果直接计算提升率。

| 框架 | baseline 官方 RPS | baseline p99 | static 官方 RPS | static p99 |
|---|---:|---:|---:|---:|
| cnetmod `e1c6da60` | 1,196,473 | 19.19 ms | 273,137 | 66.33 ms |
| agensio 固定镜像 | 6,792,921 | 1.41 ms | 995,550 | 14.02 ms |
| genhttp-ioxide 固定镜像 | 1,324,579 | 12.00 ms | 211,298 | 61.73 ms |

18/18 轮均为 0 failed、0 errored、0 timeout、0 非 2xx。
cnetmod static 三轮内存峰值为 187/200/200 MiB，baseline 为 143/163/168 MiB。
三个框架的全部轮次、headline、官方选优、延迟、CPU、内存和逐秒 RSS 均保留，见
`official-isolated/summary.json`、`records/` 和 `official-selected/`。

本轮修复了已定位的生命周期缺陷，但性能目标尚未全部达成：cnetmod static 吞吐高于
genhttp-ioxide，baseline 低于它；两项都明显低于 agensio，static p99 也没有领先。
不能把 C++ 或无栈协程本身视为最高性能的证明，也不能把这轮正确性修复称为性能极限。

## 同进程 static 保持测试

正式对照结束后，单独用相同二进制、隔离 loopback 和负载参数运行 12 轮 static，
只有 `RUNS=12` 不同。此组不参与三轮排名。共完成 17,478,533 个请求，12/12 轮均为
0 failed、0 errored、0 timeout、0 非 2xx。

每轮官方内存峰值（MiB）：`186, 196, 200, 200, 200, 199, 202, 205, 202, 201, 206, 207`。
吞吐按有效 2xx/elapsed 为 240,938–271,348 RPS。
第 3–12 轮峰值在 199–207 MiB，末轮仍较第 3 轮高 7 MiB，因此不称绝对平线，
也不能仅凭 RSS 区分分配器保留与实际活对象。本次证据覆盖的是有限持续负载窗口；
没有用手动 GC、强制清堆或逐轮重启进程制造回落。
原始日志、每秒 RSS、镜像 ID 和所有轮次见 `static-retention-12/`。

所有原始证据按字节保留，`manifest.json` 记录 SHA-256；目录级 `.gitattributes` 禁止
Git 换行转换破坏哈希。测试脚本依赖 aioquic/pylsqpack，实际路径和环境见各组记录。
