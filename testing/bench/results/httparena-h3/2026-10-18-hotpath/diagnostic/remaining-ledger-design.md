# Recovery visitor design — not implemented

This is a design review, not an applied patch or a performance claim. The current ACK range-validation correction is separately implemented and has old-failing/new-passing evidence in [ack-range-validation](ack-range-validation/README.md). The visitor, range merge and single-ledger alternatives below are deferred. This round prioritizes PMTU correctness and platform acceptance; iterator lifetime must not be traded for throughput.

Source locations refer to the dirty worktree after the ACK correction. `loss_detection.cppm` SHA256 is `81b2090c49c28ed28dadca2685b63c299850527222adee0d5e0df65916a1898e`; `quic_recovery.cpp` is `45cd8c5230516781d3d7451bde235b56e835bbfa180fd43f1ac2715f0c60374e`.

## Work that could be removed

`loss_detector::on_ack_received` (`loss_detection.cppm:78`) already uses one `lower_bound` per ACK range and walks only tracked entries. It appends each selected PN to `newly_acked` at line 125 and erases the detector node. Recovery then reads that vector and performs `sent.find(PN)` for each PN (`quic_recovery.cpp:144–178`). Loss selection similarly appends PNs at `loss_detection.cppm:182`, followed by another per-PN `find` at `quic_recovery.cpp:197–220`.

Eliminating these intermediate PN vectors can remove their capacity growth allocations, scalar copies and destruction. An empty vector allocates nothing; a nonempty vector can grow several times. Neither the number of allocations per ACK nor a CPU gain is established by this source review. Removing per-PN tree searches is a separate potential saving. It does not remove either ordered map, node insertion/extraction, bounded caches, frame ownership, or the public recovery event vectors.

Current system-GSO-on sampling estimates named recovery insertion/recycling at about 1.13 microseconds per completed static request and generic tree remove/balance at about 1.04 microseconds. Generic tree symbols cover multiple maps and cannot all be assigned to recovery. These figures are CPU/completion multiplied by sample shares, not exact timers or an achievable visitor benefit. See [system-perf-off-on](system-perf-off-on/README.md). A visitor is only one subset of the remaining roughly 23 microseconds of sampled user work.

## Public facade and private kernel

Keep both public `loss_detector` signatures, their vector return order and errors. The exported standalone detector remains usable without a recovery controller. A private walker could serve two internal sinks: a public-wrapper sink that pushes PNs into the existing vector, and a recovery sink that consumes PNs. The full range prevalidation at `loss_detection.cppm:93` must precede all RTT, largest-ACK, flight, callback and ownership changes. Invalid ACKs must invoke no sink.

The smallest non-template interface would use a private function pointer and borrowed stack context, conceptually `void (*)(void*, uint64_t)`, plus private ACK/loss walk methods. It needs no `std::function`, heap-owned callback, coroutine or new public visitor type. Declare it in the partition interface and put non-template bodies in `loss_detection.cpp`. An explicitly exported forward declaration of the existing `quic_recovery_controller` followed by private friendship can grant access without importing the recovery partition back into the loss interface. `quic_stream.cppm:33,133` already uses the forward-declaration/friend pattern for `quic_connection`. The eventual module build must verify the chosen declaration arrangement on both compilers.

A private templated walker with an inline lambda is the alternative when per-packet indirect-call cost matters. Its body must remain visible in `.cppm` under the template rule; public non-template wrappers belong in `.cpp`. It may permit inlining but increases instantiated code and interface dependency. No evidence yet chooses it over the non-template pointer. Neither form resolves ownership/reentrancy by itself.

## Range order and the second map

ACK ranges are visited from higher ranges to lower ranges; entries within one range are ascending. For example, `[7,8]` then `[2,3]` produces `7,8,2,3`, not global ascending order. Empty ranges produce no callback. The public facade must retain this ordering.

Subject to the lifetime conditions below, recovery could initialize its cursor with `sent.lower_bound(PN)` on the first callback and whenever `PN < previous_PN`. Otherwise it advances through the current range using the successor returned by extraction. A separate begin-range callback is optional; detecting the PN decrease also handles skipped empty ranges. For loss, selected PNs are ascending, so a single cursor starts at `sent.begin()` and advances over retained entries. With A acknowledged packets, R nonempty ACK ranges and L losses, this replaces A+L logarithmic `find` operations with R lower-bounds and ordered traversal; ACK ranges containing no tracked packet do not require scanning their numeric span.

The key-set assumption must be checked, rather than silently dereferencing a presumed matching key. Normally detector and recovery maps receive the same recovery-tracked PNs (`quic_recovery.cpp:129–135`), and paired removals occur on ACK/loss, space discard, probe cleanup and early-data removal (`278`, `306–311`, `331–337`). ACK-only PNs appear in ranges but in neither map. PTO alias resolution clears frame payloads without erasing their ledger entries (`183–193`); `take_outstanding_frames` also moves payloads while retaining keys (`292–303`). These facts support a merge under ordinary serialized operation, but the malformed-ACK defect showed that duplicated state can diverge. Internal invariant checks or a correct fallback are required before assuming equality.

Preserve controller ordering: compute whether aliases exist before acknowledging packets; collect delivered frames; finish alias payload removal; update congestion RTT; then detect/process loss. Moving alias cleanup into each per-PN callback can suppress or duplicate retransmission differently. Preserve the current reverse-per-packet lost-frame extraction, ordinary/probe byte separation, and wire-flight retention for a PTO alias whose payload is already delivered.

## Exceptions and owner release are the blocking boundary

An immediate recovery sink is not inherently `noexcept`. `acknowledged_path_mtu_probes`, `delivered_frames`, `lost_path_mtu_probes` and `lost_frames` can allocate. Do not mark the callback pointer `noexcept` while calling those operations, turn allocation failure into protocol rejection, or claim rollback that is absent. The existing facade has no strong allocation-exception guarantee: prior packets and RTT can already be updated when a later vector growth throws. A streamed dual-map implementation changes that partial-commit ordering and needs an explicit review; malformed ACK atomicity remains mandatory and distinct from `bad_alloc` behavior.

There is also an actual potential user-code boundary. `quic_send_frame::shared_stream` accepts an arbitrary `shared_ptr<const string>` (`quic_send_pipeline.cppm:36–38`). `recycle_sent_packet` extracts a node, saves its successor, then clears the mapped object (`quic_recovery.cpp:110–120`). Clearing the final shared owner may synchronously run its custom deleter. A deleter can observe recovery, and a mutating reentry can invalidate retained map iterators. This review does not establish a supported general mutating-reentry contract for the existing controller; it also does not justify adding a new prohibition merely to enable an optimization.

The original detector finishes its whole ACK walk before recovery releases acknowledged body owners. A new immediate visitor may retain the detector's next iterator while the recovery callback releases one. Consequently **retaining `sent.find` alone is insufficient**: the new detector iterator could also become stale. Saving `std::next` before erasure does not protect it from nested clearing. No iterator/reference may be used after a potentially reentrant release without a proven lifetime barrier or safe relocation. Caching an end iterator is not a substitute.

Loss is a narrower favorable case: moving every frame into `update.lost_frames` before clearing its node retains body ownership through the traversal on the successful path. ACK processing when aliases exist similarly moves acknowledged frames into `delivered_frames`; those owners remain live through alias cleanup. Ordinary no-alias ACKs release their frames directly, so they lack this protection. These are useful restricted cases to review, not proof that an unconditional visitor is safe. Allocation failure and all move/clear paths still need checking.

Deferring every acknowledged frame into a new vector would provide a release barrier but may replace a small PN vector with a much larger frame/owner vector and extra refcount work. Fixed storage must have a real overflow policy. Reusing the 64-node caches to retain body owners would violate their prompt-release requirement. Mutation epochs, deferred reentry queues or a new public no-reentry contract would expand the change beyond the intended small hot-path patch. None is proposed for this round.

## Three independent implementation sizes

| Direction | Potential saving | Safe acceptance boundary |
| --- | --- | --- |
| PN visitor, retain per-PN second-map `find` | PN vector growth/copies only | Callback must not expose a live detector cursor to owner release; otherwise keep the original path. Allocation and exception ordering still require review. No general static gain is established. |
| Restricted ordered range merge | Also removes repeated `find` in eligible ranges | Use only a proven no-release traversal or a separately justified release barrier; fall back for unsupported owner paths. Both maps' membership and ACK/loss order must remain equal. Ordinary shared-body ACKs are not automatically eligible. |
| One ledger with shared metadata ownership | Can remove duplicated nodes, insertion, lookup and retirement | Larger architectural change affecting RTT/loss, congestion, PMTU, aliases, discard/copy/move and public facade adaptation. It is outside this round. |

The first row is a smaller experiment, not an automatically safe stepping stone to the second. A benchmark improvement cannot establish the missing lifetime contract. The current implementation is retained while PMTU and platform correctness are completed.

## Behavior coverage and remaining tests

Current tests already cover malformed ACK state/owner atomicity (`test_quic_loss_detection.cpp:49,503`), valid zero-boundary/duplicate/stale ACK (`107`), ACK-only holes (`283`), unsent ACK (`305`), PN-space isolation/discard (`359,392`), original/PTO-alias ownership (`434,545`), repeated bursts beyond cache capacity (`585`), loss ownership transfer (`620`), discard/reuse and copy/move (`651,682`), PMTU loss and mixed ordinary/probe loss (`723,758`), and probe PTO cleanup/reliable payload retransmission (`786,813,832`). The latest correction passes 27 detector/recovery cases plus 17 stream and 20 congestion cases. Those results do not validate an unimplemented visitor.

If revisited, add behavior cases for several descending ranges with ascending entries inside each range, empty tracked ranges between populated ranges, ACK-only holes plus packets above the largest ACK, and successive valid ACK frames arriving out of order. Verify public vector order and duplicate/stale no-op behavior. Use multiple frames in one lost packet to pin reverse extraction order, plus original and alias acknowledged in different ranges. Repeat the malformed rejection/follow-up valid ACK owner test. Exercise full-width public gaps without enumerating packet-number spans.

Owner tests must cover when the last shared owner disappears, not just a final weak-pointer assertion. A custom deleter that observes public recovery state can detect an earlier release phase; any contemplated mutating-reentry support needs its own explicit contract and regression rather than assuming existing serialization covers a deleter. Allocation-failure testing must identify the existing and proposed partial-commit behavior, without a test-only global allocator override. Differential results against the unchanged facade and a same-input old control are stronger than tests that repeat a cursor helper's implementation.

For performance, only after those boundaries close: compare the same allocator, PMTU, GSO setting, source layout and workload; record actual allocation calls and completed-request CPU/throughput separately. Empty loss passes offer no vector allocation to remove. A smaller relative tree/AES percentage is not a measured absolute saving, and the older mimalloc profile cannot supply the current per-ACK allocation count.
