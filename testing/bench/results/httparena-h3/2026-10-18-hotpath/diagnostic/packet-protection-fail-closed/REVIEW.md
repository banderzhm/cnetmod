agent. The external fault fixture has not yet been compiled or exercised.

## Patch boundary

Only `quic_connection.cppm` and `quic_connection.cpp` change. Four private helpers
return `std::expected` so an empty value still means no eligible packet and an
error means protection failed. Public APIs, write completion timing, frame/alias
identity, UDP batching, PMTU, congestion control, and global `make_ssl_error`
semantics remain as before. No new connection state, helper allocation, file, or
normal-path post is introduced. Expected adds a result discriminator and changes
private coroutine result types; its performance/compilation has not been tested.

`append_sealed_payload` and `protect_header` errors are normalized locally to
nonzero `generic:io_error` when the backend returns an empty error code. Preserve
an existing nonzero category/value exactly. Errors are not retried, and frames
are not restored: this policy terminates the entire connection.

## Prefix and lifetime

The batch builder returns on the first protection error, while no datagram in
that batch has been submitted. Its local vector prefix is destroyed; it does not
notify timers, pace, send, or restore packet buffers into the connection pool.
The enclosing receive guard unlocks before the error reaches the close boundary.
The same rule drops already-built but unsubmitted PTO probes.

The normal flush boundary still holds the unique writer claim, invokes
`close_transport`, then returns immediately. No path reference, stream iterator,
packet pool, queue size, or other connection state is read after that close call.
The existing guard releases its writer claim during return. Existing async
member lifetime rules still require the caller to retain the connection until
the operation completes; `async_close` already joins this writer. This proposal
does not claim to make destroying a connection with live member tasks safe.

PTO reports errors to the unlocked timer boundary; startup reports them to the
existing `run` wrapper. Network terminal send errors now use the same outward
propagation instead of closing inside a helper and then continuing buffer-pool
cleanup. Network nonterminal handling is unchanged.

## Public completion limit

The existing internal queue-acceptance completion remains before packing and is
not completed a second time. A public call which already returned success cannot
be changed retroactively. An internal accepted completion does not guarantee a
public call will return success: `async_send`/`async_send_shared` retain their
existing post-completion `terminal_send_error` checks. In particular a writer
still awaiting its own flush can return the terminal error. Queued commands are
failed by `close_transport`, and later writes fail promptly.
The fixture asserts only the writer which still owns and awaits this flush,
plus a subsequent write. It deliberately makes no promise about earlier
accepted writes, peer ACK, or successful delivery.

## Real failure regression, prepared but not run

`quic_packet_failure_server.cpp` is a dedicated raw QUIC fixture copied from the
existing Retry-correct retirement fixture. It uses a single response write of
4096 bytes and a 6-second idle deadline. A test-only connection implementation
copy counts response packets: the first commits to recovery, the second fails
protection. The real library failure is not a syscall mock or public test hook.

`inject_fault.py` transforms either the original or candidate implementation
into a new external source. Link its object only into the dedicated fixture,
using an isolated copied archive and the same latest PCM/runtime as appropriate.
It depends on private implementation symbols and must be reviewed/rebased after
concurrent PTO or packet-owner changes. Do not replace a production archive.

Fault cases:

- `seal`: copy the active immutable keys, set local `tag_len=0`, call the actual
  append helper. AEAD still requires its real 16-byte tag, but no tag output is
  available: BoringSSL returns `CIPHER_R_BUFFER_TOO_SMALL` in `openssl` category.
- `hp`: after actual sealing, clear only the local key copy's HP key and call
  actual `protect_header`, which returns `generic:invalid_argument`.
- `seal-empty-error`: trigger the same real AEAD failure, then replace only its
  reported error code with zero to simulate an empty backend error queue. This
  extra reporting fault is explicitly synthetic. Require `generic:io_error`.

The fixture callbacks record exactly two selected response packet attempts, one
successful commit, and one observed real crypto failure. This proves a prefix
actually existed. The Python peer requires a nonzero error/closed state and a
failed subsequent write within 500 ms, well before idle; it also requires zero
response bytes, proving the prepared prefix was not sent after the fatal error.
It runs observer and private receive modes. Both use the single-path batch path.

Use the identical fixture/injection on original and candidate libraries. Old
code is expected to report accepted/connected (and possibly send its prefix),
which is a failure of this regression; new code must meet every assertion.
Neither negative nor positive control has been executed.
