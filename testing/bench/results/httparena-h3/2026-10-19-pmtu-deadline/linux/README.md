# Preserve scheduled QUIC PMTU probe deadlines

Accepted scope in this validation: one production condition adds !path->next_path_mtu_probe_at to arm_path_mtu_discovery. Ordinary authenticated short packets can repeatedly call arm even when connected; the guard preserves the deadline already installed by first readiness or by probe ACK/loss/PTO. No stride, cap, application/CC semantics, pending-probe deferral, PTO selection, or adaptive search change is included.

Real old/new fixture: quic_pmtu_deadline_server.cpp, quic_pmtu_deadline.py and deadline_frame_parser.py, with two CTests. The dedicated server uses actual process_datagram/async_poll_timers and replaces its latest timer schedule after ingress/poll, avoiding incidental rescue by HTTP/3's older timer heap entry. Stock unmodified aioquic1.7.0, no AEAD adapter, max UDP1452. The transparent proxy independently authenticates both directions, extracts actual ACK ranges and PING/PADDING probe identity, and forwards original packets unchanged. No fake ACK, timer pause, CC setter, secret or raw traffic dump.
