# HTTP/2、TLS 与压缩踩坑记录

## 同场景 A/A 决定小幅收益能否采信

2026-11-09 将适配器的 50 个 JSON 视图槽位改为线程本地复用。4 worker 的三组
H2C 吞吐均上升，中位约 +2.58%，七组响应字节一致。但同场景、同旧二进制的 A/A
变化约为 -8.79%、-28.73%、+17.45%，无法确认这次收益。因此候选已撤回。
只看候选连续三次上升仍不足以越过未通过的噪声门禁。

## JSON 响应缓冲复用

2026-11-09 将适配器的 JSON 路由改为复用现有 `respond_json()`，通过
`generate_body()` 和 `json::write_to()` 直接生成响应。七组官方参数轮换下，
H2C 的 4/8 worker 配对中位数约为 +1.23% / -2.69%。官方 TLS Lua 轮换在
4 worker 下约下降 9.28%。候选已撤回，逐轮数据见执行记录。

响应字节比较通过，所有有效压测均无请求错误。局部少一个临时字符串仍不足以决定保留，
需要同时检查不同传输路径的完整请求成本。本轮未定位回退的具体原因。

## HPACK

### 不要在通用编码器里缓存最后一个响应头块

方案：连接编码器保存最近一次不修改动态表的 HPACK 结果。

结果：固定响应在 4、8 worker 分别提升约 3.9% 和 1.9%，16 worker 基本持平。轮换 JSON-H2C 在 4 worker 下降约 1.4%，CPU/请求增加约 1.4%。

原因：命中时省下表扫描，未命中时却增加字段比较。动态 JSON 的正文长度频繁变化，因此每个请求都承担检查成本。

重新尝试条件：调用方能在进入通用编码器前提供稳定的响应形状标识。

### text/plain 专用缓存仍然不值得保留

方案：只缓存连续的 `200 + text/plain + 相同正文长度`。

结果：冷却后的 8 worker ABBA 四组配对为 -3.5%、-0.3%、+1.5%、-4.0%，配对中位数约 -1.9%。

原因：即使缩小判断范围，连接内状态维护和分支仍没有减少完整响应路径的主要成本。

重新尝试条件：路由注册时直接绑定固定元数据，运行期不再识别响应形状。

### 静态表 HPACK 块可能比动态编码更慢

方案：应用显式绑定一个长期有效的 HPACK 块，不使用 `shared_ptr`，也不执行缓存查找。

结果：4 worker 三轮约 -0.9%、-0.8%、-3.4%，CPU/请求变差；8 worker 接近持平。

原因：连接无关的块只能使用静态表和 literal。连接进入稳态后，动态表引用更短。少做编码却发送更多字节，整体仍然变慢。

重新尝试条件：协议允许稳定复用动态表索引，或者响应头不会进入动态表。

## TLS 与 HTTP/2 批处理

### 响应批次年龄不是当前瓶颈

方案：把 HTTP/2 响应 batch age 从 250 微秒降到 50 微秒。

结果：预热后中位数从 6.321M/s 变为 6.334M/s，只提高约 0.21%。

原因：改动低于保留门槛，无法覆盖调度噪声。

### TLS BIO 阈值不能靠直觉调大或调小

方案：把直接发送阈值从 8KiB 改为 64KiB，另一候选改为 4KiB。

结果：JSON-TLS 分别下降约 0.83% 和 2.68%。

原因：阈值同时影响 BIO 复制、TLS record 聚合和 socket 写入次数。单独减少其中一项会把成本转移到另一项。

结论：保留 8KiB。

## 静态正文

### 16KiB 是当前 HTTP/2 借用边界，32KiB 不是

把动态正文借用阈值从 4KiB 提高到 16KiB，使 static-H2 从 350.55K/s 提升到 365.17K/s，baseline-H2 和 JSON-H2C 也改善。继续提高到 32KiB 没有保持收益。

另一个候选只保存一个正文 owner，而不是每个借用帧保存 owner，中位数下降约 0.87%。生命周期对象变少，不代表访问路径更短。

结论：保留 16KiB，不合并 owner 去重方案。

## JSON 压缩

### 原始吞吐提高不等于 json-comp 得分提高

方案：从 Brotli quality 2 切换到 gzip level 1。

结果：4/8/16 worker 的原始吞吐提高约 2.0%–7.5%。三个官方响应由 989、1349、1600 字节增至 1126、1627、1958 字节。

HttpArena 使用 `RPS × (最小每响应字节数 / 当前每响应字节数)²` 计算该项目。体积惩罚后，候选得分约下降 25%。

结论：保留 Brotli quality 2。以后调整压缩参数时，必须同时记录 RPS、带宽和每响应字节数。
