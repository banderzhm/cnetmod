# HttpArena 踩坑索引

这里记录已经实现、编译并压测，但最终没有保留的优化方案。它与推进日志的职责不同：

- 推进日志保存时间顺序、原始轮次和当时的决策；
- 本目录按问题类型整理结论，方便后来的人在改代码前快速排除旧路；
- 某个方案只有在“重新尝试条件”发生变化后才值得重做。

## 分类

| 文件 | 范围 | 主要结论 |
|---|---|---|
| [HTTP/1.1 与 WebSocket](http1-websocket.md) | 解析、响应复用、连接生命周期、帧解析和写入提交 | 小对象缓存、额外分支和共享所有权很容易抵消节省的复制 |
| [HTTP/2、TLS 与压缩](http2-tls-compression.md) | HPACK、响应批处理、TLS 阈值、静态正文和 JSON 压缩 | 固定响应变快不代表动态响应会变快；压缩项目必须同时计算编码体积 |
| [HTTP/3 与 QUIC](http3-quic.md) | QPACK、请求对象复用、STREAM 布局、worker 亲和性和静态文件 | QUIC 热路径对对象布局、调度和所有权变化非常敏感，局部少一次复制不一定减少整包成本 |
| [Async 延迟路由](async-timers.md) | io_uring timeout、CQE 收割、提交批量和 worker 扩展 | 单 worker 已接近理论上限；盲目扩大批量或减少事件循环都会回退 |
| [压测与判断方法](measurement.md) | 4/8/16 worker、配对顺序、温度、CPU/请求和跨项目门禁 | 单轮最好值和微基准不能决定保留；必须看配对中位数及关联场景 |

## 使用规则

开始新的性能修改前：

1. 先查本目录是否已有相同思路。
2. 若重新尝试，先写清哪些前提已经改变。
3. 使用同一二进制配置跑基线和候选。
4. 至少覆盖 4、8、16 worker。
5. 同时记录吞吐和 CPU/请求。
6. 运行会经过同一代码路径的关联项目。
7. 任一关联项目的中位数回退超过 1%，立即撤销候选。

完整轮次仍以 [推进日志](../httparena-gap-closure-log.md) 为准。
当前排名和预计剩余差距见
[第一名目标跟踪表](../httparena-target-tracker.md)。
